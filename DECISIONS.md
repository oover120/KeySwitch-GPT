# Решения

1. .NET 8, C# 12, Windows x64, WPF + системный NotifyIcon, без главного окна. UI: Segoe UI Variable; системная тема, спокойный синий акцент #0067C0; фон #F3F3F3 / #202020, текст #191919 / #F5F5F5. Вкладки и вертикальные группы; никаких экранов первого запуска.
2. Полностью локальная работа. Интернет применяется только инструментом подготовки открытых моделей во время разработки, в исполняемом приложении сетевых API нет. Никаких журналов символов или контекста; обучение хранит только явно подтверждённые пользователем слова и счётчики.
3. Частотные словоформы: Hermit Dave, FrequencyWords 2018, OpenSubtitles, CC BY-SA 4.0 (https://github.com/hermitdave/FrequencyWords, README явно отделяет MIT для кода от CC BY-SA для данных). Производные списки сохраняют CC BY-SA 4.0; атрибуция и полный текст лицензии поставляются рядом с приложением. Код генератора не копируется.
4. 3–4-граммы обучаются отдельно на train-разделах UD English EWT и Russian GSD (CC BY-SA 4.0 для аннотаций/базы). Исходные тексты EWT имеют дополнительные авторские права; не распространяем предложения корпуса, только агрегаты символьных счётчиков. Лицензии, атрибуция, ссылки и SHA-256 исходников включены в assets/sources.json и licenses. Test-разделы не участвуют в обучении. Источники: https://github.com/UniversalDependencies/UD_English-EWT и https://github.com/UniversalDependencies/UD_Russian-GSD.
5. Консервативное решение: известное исходное слово сохраняется; неоднозначные короткие слова, адреса, код и смешанные алфавиты сохраняются. Доля пропусков честно отражается Evaluate; целевые 98%/0.5% — критерии, а не обещание без измерения.
6. UI Automation и сведения о процессах получаются вне LL-хука. Цель и поколение фокуса проверяются перед каждой операцией. Потеря фокуса отменяет запланированную замену. Политика результата UIA для версии 1.0.1 описана в п. 15.
7. Замена отправляется одним пакетом SendInput. Исходный разделитель подавляется только при подготовленной замене. События пользователя во время транзакции удерживаются и возвращаются по порядку. Собственный dwExtraInfo + INJECTED исключает рекурсию. Синтетический ввод с меньшим уровнем целостности пропускается и сбрасывает историю.
8. Двойной Shift распознаётся на отпускании: два коротких тапа <400 мс без других клавиш. Undo доступно только пока курсор непосредственно после исправления; любое редактирование/мышь/смена фокуса его инвалидирует. Это предотвращает стирание чужого текста.
9. Парольный эвристический фильтр срабатывает на длине >6, сочетании строчных, заглавных и цифр/знаков. Нельзя надёжно отличить пароль от обычного идентификатора: такие слова никогда не учатся и не исправляются автоматически.
10. Автозапуск изменяется только при действии пользователя; стандартный режим HKCU Run. Опция повышенного запуска создаёт задачу текущего пользователя с InteractiveToken/HighestAvailable через schtasks после UAC; пароль пользователя не запрашивается и не хранится.
11. Публикация self-contained single-file относится к программе; файлы лицензий остаются рядом. WPF trimming отключён. Inno Setup — отдельный внешний инструмент, его отсутствие не подменяется фиктивным установщиком.
12. После замера памяти словари и n-граммы упакованы в сортированные UTF-8 пулы вместо управляемых строк и хеш-таблиц. Размер модели не уменьшали, чтобы сохранить результаты детектора. Порог оптимизирован на корпусном тесте, поэтому отчёт служит проверкой регрессий и не является слепой оценкой.
13. Инсталлятор для текущего пользователя. Он сохраняет данные в AppData при удалении и снимает созданные продуктом записи автозапуска. Для задачи администратора может потребоваться UAC. Компилятор Inno Setup 6.7.3 используется в переносном режиме, подлинность исходного пакета проверяется до запуска.
14. Chrome до исправления. Журнал показал `context-not-ready`, `wordLength=6`, `bufferedLength=0`. Разделение этапов подтвердило `contextError=process-image`, Win32 `5` и `passwordCheck=not-queried`. Перечисление модулей через `Process.MainModule` требовало доступа, недоступного к наблюдавшемуся процессу. Используем `QueryFullProcessImageNameW` с `PROCESS_QUERY_LIMITED_INFORMATION`. Готовность контекста зависит от нативного фокуса и доступности пути, результат UIA хранится отдельно.
15. Проверка `IsPassword` асинхронна и кэшируется на поколение фокуса. Бюджет 50 мс, максимум один параллельный вызов к провайдеру. `Error`, `Unknown` и `Timeout` не считаются паролем. Поздний явный `true` применяется только к тому же фокусу. События заголовка игнорируются, повторы одного события фокуса не очищают буфер. Браузеры из списка не считаются играми. Для остальных учитываются список игр, папка `Games` и индикатор эксклюзивного Direct3D fullscreen.
16. Текущий HKL берётся у потока `hwndFocus`. `WM_INPUTLANGCHANGEREQUEST` публикуется в очередь поля и корневого окна. После запроса проверяется HKL и при необходимости выполняется один повтор. Для браузеров и Electron введена пауза 10 мс между стиранием и набором. Win32 `KEYBDINPUT.time` задаёт отметку времени события и не планирует задержку. Поэтому там два вызова SendInput с тем же `dwExtraInfo`, удержанием очереди и перепроверкой фокуса. В остальных приложениях используется один пакет. См. [WM_INPUTLANGCHANGEREQUEST](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-inputlangchangerequest) и [KEYBDINPUT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-keybdinput).
17. Журнал диагностики включается явно. Поля схемы содержат только технические атрибуты. Длина до фильтров считается отдельно от рабочего буфера, поэтому виден случай, когда ввод распознан хуком, но буфер пуст из-за проверки контекста. Запись и ротация выполняются вне хука.
18. Начиная с 1.0.2, `word`, `buffer-reset` и `ignored` имеют уровень INFO и пишутся всегда. `--debug` добавляет снимки фокуса уровня DEBUG. Счётчик до фильтров не содержит символов и сохраняется при сбросе буфера до разделителя. Обработчик разделителя и отложенная замена используют одну итоговую запись. Диагностика пропущенных клавиш ограничена одной записью в секунду.
19. ESET Smart Security Premium 20: пользователь подтвердил контрольным переключением, что при выключении «Защиты клавиатуры» автоматическая смена раскладки работает, а при повторном включении перестаёт работать. Это несовместимость текущего глобального клавиатурного хука с защищённым браузерным вводом. По [официальной документации ESET](https://help.eset.com/essp/20/en-US/idh_config_sb.html), эта опция скрывает ввод от других приложений. Наличие `ekrn.exe` или низкая оценка детектора сами по себе не доказывают включение защиты; не присваиваем всем таким отказам причину `ESET`. Порог детектора не снижаем, защиту из приложения не отключаем. Совместная работа с включённой опцией и исключение для KeySwitch не подтверждены. Успешный контрольный тест подтверждён пользователем, а не строками доступного журнала.
